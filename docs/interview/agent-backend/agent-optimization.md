# Agent 开发调优面试题

## 1. Agent 效果不好如何排查？

按链路拆解：

1. 用户意图是否识别正确？
2. Prompt 是否明确角色、目标、约束和输出格式？
3. 工具 schema 是否清晰？
4. 工具结果是否过长或噪声太多？
5. 上下文是否缺失或被无关信息干扰？
6. 模型是否适合该任务？
7. 是否有评测集和失败样本归因？

## 2. Prompt 如何调优？

通用原则：

* 明确目标：告诉模型要完成什么。
* 明确边界：告诉模型不能做什么。
* 明确格式：使用 JSON schema 或示例约束输出。
* 明确决策规则：什么时候调用工具，什么时候直接回答。
* 提供 few-shot：覆盖典型和边界样例。
* 控制上下文：减少无关内容。

常见结构：

```text
角色定义
任务目标
可用工具
调用规则
输出格式
错误处理策略
示例
用户输入
```

## 3. 如何避免 Agent 无限循环？

措施：

* 设置最大步数和最大工具调用次数。
* 对相同工具+相同参数做重复调用检测。
* 维护任务状态，要求每一步必须产生状态变化。
* 工具失败达到阈值后走 fallback。
* 让模型在每轮判断是否已经满足完成条件。

## 4. 如何降低 Agent 延迟？

优化点：

* 减少 LLM 调用轮数。
* 小模型做意图识别，大模型做复杂推理。
* RAG 检索、工具调用并行化。
* 缓存稳定结果，如系统 prompt、检索结果、工具结果。
* 使用流式输出改善体感。
* 控制上下文长度，压缩工具返回。

## 5. 如何降低成本？

措施：

* Prompt 压缩，减少历史上下文。
* 模型路由：简单任务走便宜模型。
* Embedding 和检索结果缓存。
* 工具结果摘要化。
* 批处理离线任务。
* 对高频问题使用 FAQ 或模板直出。

## 6. 如何提升工具调用准确率？

关键点：

* 工具名称语义明确。
* 参数 schema 尽量使用枚举、范围和描述。
* 工具数量不要过多，必要时先做工具路由。
* 给出正反例，说明什么时候不能调用。
* 后端对参数做强校验，失败时返回可修复错误。

## 7. Agent 评测怎么做？

评测维度：

* 任务成功率
* 工具调用准确率
* 参数正确率
* 幻觉率
* 平均步骤数
* 平均耗时
* token 成本
* 安全违规率

评测方法：

* Golden Set：人工标注标准答案和期望工具调用。
* Trace Replay：回放真实线上请求。
* LLM-as-Judge：适合开放问答，但要做抽样人工校验。
* A/B Test：比较不同 prompt、模型和检索策略。

## 8. 线上 Agent 如何观测？

必须记录：

* request id / session id / user id
* prompt 版本和模型版本
* 每轮输入输出 token
* tool call 参数、耗时、状态码
* RAG 检索 query、召回文档、score
* 最终答案、用户反馈、错误栈

注意脱敏，敏感字段不要明文落日志。
